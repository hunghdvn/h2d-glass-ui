# Getting started

h2d-glass-ui is a glassmorphism component library for React 18.3+ and 19. It ships plain CSS and
works in React Server Components.

## Install

```bash
pnpm add h2d-glass-ui
```

## Load the styles once

```tsx
import 'h2d-glass-ui/styles.css';
```

All library CSS lives in the `flg` cascade layer, so any CSS you write outside a layer overrides it
without `!important`.

## Use a component

```tsx
import { Button, Card, CardContent, CardFooter, CardHeader, CardTitle } from 'h2d-glass-ui';

export function Upgrade() {
  return (
    <Card>
      <CardHeader>
        <CardTitle>Upgrade to Pro</CardTitle>
      </CardHeader>
      <CardContent>Unlimited sync and priority support.</CardContent>
      <CardFooter>
        <Button variant="ghost">Not now</Button>
        <Button>Upgrade</Button>
      </CardFooter>
    </Card>
  );
}
```

Phase 1 components: Surface, Card, Button, IconButton, Badge, Avatar, Divider, Spinner, Field,
Input, Textarea, Checkbox, RadioGroup and Switch. Phase 2 adds Dialog, Drawer, Popover, Tooltip,
DropdownMenu, ContextMenu, Select, Tabs, Accordion, Breadcrumb, Pagination and Toast. Phase 3 adds
the advanced inputs: Slider, NumberInput, SegmentedControl, Combobox, TagInput, FileUpload, Calendar
and DatePicker. Phase 4 adds the display of data and of progress: Alert, Progress, Skeleton,
Stepper, List and Table. Phase 5 adds the frame of an application: AppShell, Nav, Indicator,
SearchField, ThemeSwitch and UserMenu.

## Overlays

Dialog, Drawer, Popover, Tooltip, the menus and Select are built on the native `<dialog>` element and
the Popover API, so there is no portal and no z-index to manage: an overlay renders next to its
trigger and sits above the page.

Toast is the exception. The `<Toaster />` has no trigger: it renders where you place it, as a
popover above the page. While a Dialog or Drawer is open it moves its region into that modal's host
(a portal), so the toasts can still be seen, clicked and read.

Put a `<Toaster />` once near the root of the app, then call `toast()` from client code:

```tsx
import { Toaster } from 'h2d-glass-ui';

export function App({ children }: { children: React.ReactNode }) {
  return (
    <>
      {children}
      <Toaster />
    </>
  );
}
```

A `<dialog>` that this library did not create is not part of its overlay stack. A modal one makes
the rest of the page inert, the toasts among it, so they sit under it and cannot be clicked; the
library's own Dialog and Drawer carry the toasts inside them instead. Open a modal through the
library's Dialog when toasts must stay reachable.

## Build a form

Wrap each control in a `Field` for its label, description and error. Every control is a native
form element underneath, so `FormData`, the browser's validation and form libraries work as usual.

```tsx
import { Field, Input } from 'h2d-glass-ui';

<Field label="Email" description="We only use it to send sign-in links." error={errors.email}>
  <Input name="email" type="email" autoComplete="email" />
</Field>;
```

The advanced inputs of phase 3 work the same way:

- **Every control submits with a plain form and resets with it.** Slider, NumberInput,
  SegmentedControl, Combobox, TagInput, FileUpload and DatePicker (Calendar is the exception: it
  holds no form value) put their value in the form's `FormData` under `name`, with no extra
  JavaScript, and go back to their `defaultValue` when the form is reset. A controlled control keeps
  the value its parent gives it. Each one, and Select, takes a `form` prop (a form id), so a control
  outside the `<form>` still submits and resets with it.
- **Values are numbers and ISO strings.** Slider and NumberInput give a `number` (a range Slider
  gives `[number, number]`). Dates are `'YYYY-MM-DD'` strings and months `'YYYY-MM'`, never `Date`
  objects, so a date does not move with the time zone and the server and the browser agree. In a
  controlled Combobox, NumberInput, DatePicker or Calendar, `null` means no value; `undefined`
  means uncontrolled. `onValueChange` runs when the user changes the value, not when your code does.
- **`locale` and `weekStartsOn`.** NumberInput, Calendar, DatePicker and FileUpload (the size of a
  file) take a BCP 47 `locale`, `'en-US'` by default so that the server and the browser print the
  same text. The library does not guess the first day of the week from the locale: Calendar and
  DatePicker start on Sunday, so set `weekStartsOn={1}` for a locale whose week starts on Monday,
  such as `vi-VN`.
- **Function props must come from a client component.** `getValueText`, `filter`, `validate`,
  `isDateUnavailable`, `onReject` and a `labels` object with functions in it cannot cross from a
  Server Component. Wrap the component in a client component of your own, as for Pagination's
  `getHref`.

```tsx
'use client';

import {
  Button,
  Combobox,
  ComboboxItem,
  DatePicker,
  Field,
  NumberInput,
  Slider,
} from 'h2d-glass-ui';

export function BookingForm() {
  return (
    <form action="/book" method="post">
      <Field label="Guests">
        <NumberInput name="guests" defaultValue={2} min={1} max={8} />
      </Field>
      <Field label="Check-in" description="Write it as mm/dd/yyyy.">
        <DatePicker name="checkin" weekStartsOn={1} />
      </Field>
      <Field label="Budget per night">
        <Slider name="budget" defaultValue={120} min={40} max={400} getValueText={(v) => `$${v}`} />
      </Field>
      <Field label="City">
        <Combobox name="city" placeholder="Search a city">
          <ComboboxItem value="hanoi">Hanoi</ComboboxItem>
          <ComboboxItem value="hue">Hue</ComboboxItem>
        </Combobox>
      </Field>
      <Button type="reset" variant="ghost">
        Clear
      </Button>
      <Button type="submit">Book</Button>
    </form>
  );
}
```

`FormData` then holds `guests`, `checkin` (an ISO date, or an empty string with no date), `budget`
and `city`. A TagInput adds one entry per tag under the same `name`, and a range Slider adds two.

## Loading states

A page that waits has three jobs: keep its shape, tell a screen reader, and say how long when it
knows. Skeleton, Progress and Spinner each do one of them. Skeleton is always hidden from screen
readers, and Progress is not a live region, so the announcement is yours to make.

**The container stays, and its content changes.** Keep the element that holds the data mounted, set
`aria-busy` on it while the work runs and back to `false` when it ends, and swap the Skeletons for
the content inside it. Say "loading" once, from a `role="status"` region that is already in the
page, empty, before the work starts: a screen reader reads what changes in a live region it already
knows, and does not read one that is inserted with its text.

```tsx
'use client';

import { useState } from 'react';
import { Button, Skeleton, SkeletonText } from 'h2d-glass-ui';

export function WeeklyReport() {
  const [loading, setLoading] = useState(false);
  // Start the request in `refresh`, and call setLoading(false) when it ends.
  const refresh = () => setLoading(true);
  return (
    <>
      {/* `sr-only` stands for a visually hidden class of your own. */}
      <div role="status" className="sr-only">
        {loading ? 'Loading the weekly report' : ''}
      </div>
      <section aria-busy={loading} aria-label="Weekly report">
        {loading ? (
          <>
            <Skeleton shape="text" width="40%" />
            <SkeletonText lines={2} />
          </>
        ) : (
          <p>1,240 visits, up 8% on last week.</p>
        )}
      </section>
      <Button variant="ghost" onClick={refresh} loading={loading}>
        Refresh
      </Button>
    </>
  );
}
```

<Canvas of={LoadingStories.Container} />

Put each Skeleton where its content will be, at the same size, so that nothing moves when the
content arrives. A Suspense `fallback` is inserted already filled, so an announcement from inside it
is best effort; the `aria-busy` container that stays mounted is the reliable part. The
[Skeleton](?path=/docs/components-skeleton--docs) page has the shapes and the looks.

**Known progress or an unknown wait.** A `Progress` is for work whose amount you know, such as files
uploaded: give it a name, and a `getValueText` when the number matters. A `Spinner` is for a short
wait of unknown length, such as saving a form. It is a `role="status"` region of its own, so mount
it before the work starts, as above.

```tsx
import { Progress, Spinner } from 'h2d-glass-ui';

<Progress
  label="Uploading photos"
  value={done}
  max={total}
  getValueText={(value, max) => `${value} of ${max} photos`}
  showValue
/>;

<Spinner label="Saving your changes" />;
```

<Canvas of={LoadingStories.KnownAndUnknown} />

**Rows that load.** Keep the Table and its heading, and draw Skeleton `text` in the cells, one for
each column, so the columns do not move. The table carries the `aria-busy`, with the same status
region beside it:

```tsx
<div role="status" className="sr-only">
  {loading ? 'Loading the orders' : ''}
</div>
<Table aria-busy={loading}>
  <TableCaption>Recent orders</TableCaption>
  {/* The heading stays. */}
  <TableBody>
    {loading
      ? [0, 1].map((row) => (
          <TableRow key={row}>
            {[0, 1, 2].map((cell) => (
              <TableCell key={cell}>
                <Skeleton shape="text" width={cell === 0 ? 72 : 120} />
              </TableCell>
            ))}
          </TableRow>
        ))
      : orders.map((order) => <TableRow key={order.id}>{/* The cells. */}</TableRow>)}
  </TableBody>
</Table>
```

<Canvas of={LoadingStories.TableRows} />

With `prefers-reduced-motion: reduce` the Skeletons and an indeterminate Progress stand still, and a
Spinner keeps turning, more slowly: see the [Accessibility](?path=/docs/docs-accessibility--docs)
page.

## Show data

The library draws data; it does not handle it. It does not sort, filter or page: you pass the rows
in the order and the amount to show, and the components say what you tell them. A Table with
sorting, chosen rows and pages is the sort, the selection and the page, held in state of your own.

```tsx
'use client';

import { useState } from 'react';
import {
  Checkbox,
  Pagination,
  Table,
  TableBody,
  TableCaption,
  TableCell,
  TableHead,
  TableHeader,
  TableRow,
} from 'h2d-glass-ui';
import type { TableSort } from 'h2d-glass-ui';

const PAGE_SIZE = 3;

export function OrdersTable({ orders }: { orders: Order[] }) {
  const [sort, setSort] = useState<TableSort>('none');
  const [page, setPage] = useState(1);
  const [chosen, setChosen] = useState<ReadonlySet<string>>(new Set());

  const sorted =
    sort === 'none'
      ? orders
      : [...orders].sort((a, b) => (sort === 'ascending' ? a.total - b.total : b.total - a.total));
  const pageCount = Math.max(1, Math.ceil(sorted.length / PAGE_SIZE));
  const rows = sorted.slice((page - 1) * PAGE_SIZE, page * PAGE_SIZE);

  const onPage = rows.filter((order) => chosen.has(order.id)).length;
  const toggle = (id: string, on: boolean) =>
    setChosen((before) => {
      const next = new Set(before);
      if (on) next.add(id);
      else next.delete(id);
      return next;
    });

  return (
    <>
      <Table>
        <TableCaption>Recent orders</TableCaption>
        <TableHeader>
          <TableRow>
            <TableHead>
              <Checkbox
                aria-label="Select all on this page"
                checked={rows.length > 0 && onPage === rows.length}
                indeterminate={onPage > 0 && onPage < rows.length}
                onCheckedChange={(on) => rows.forEach((order) => toggle(order.id, on))}
              />
            </TableHead>
            <TableHead>Order</TableHead>
            <TableHead>Customer</TableHead>
            <TableHead
              align="end"
              sort={sort}
              onSort={(next) => {
                setSort(next);
                setPage(1);
              }}
            >
              Total
            </TableHead>
          </TableRow>
        </TableHeader>
        <TableBody>
          {rows.length === 0 ? (
            <TableRow>
              <TableCell colSpan={4} align="center" style={{ whiteSpace: 'normal' }}>
                <strong>No orders yet</strong>
                <br />
                New orders will show up here.
              </TableCell>
            </TableRow>
          ) : (
            rows.map((order) => (
              <TableRow key={order.id} selected={chosen.has(order.id)}>
                <TableCell>
                  <Checkbox
                    aria-label={`Select ${order.id}`}
                    checked={chosen.has(order.id)}
                    onCheckedChange={(on) => toggle(order.id, on)}
                  />
                </TableCell>
                <TableCell>{order.id}</TableCell>
                <TableCell>{order.customer}</TableCell>
                <TableCell align="end">{order.total.toLocaleString('vi-VN')} ₫</TableCell>
              </TableRow>
            ))
          )}
        </TableBody>
      </Table>
      <Pagination count={pageCount} page={page} onPageChange={setPage} aria-label="Orders pages" />
    </>
  );
}
```

<Canvas of={DataStories.Orders} />

- **Sorting.** `onSort` makes the title a button and gives you the direction to go to; sort the rows
  yourself and pass the new `sort`. Only the sorted column carries `aria-sort`.
- **Choosing rows.** The Checkbox in the row, named for the row, says whether it is chosen;
  `selected` on the row only draws it. The box in the heading selects every row on the page, and
  is `indeterminate` when only some of them are chosen.
- **Empty.** One row with one cell across every column (`colSpan`), in the middle, allowed to wrap.
- **Pages.** `Pagination` takes the number of pages and the current one; cutting the rows is yours.

The [Table](?path=/docs/components-table--docs) page has the rest: `stickyHeader`, the footer, the
three looks and the scroll frame.

**A List for navigation.** A row with an `href` is a link named by its title. `current` marks the
page the person is on, and `renderLink` hands the link to the `Link` of your router: pass every prop
on.

```tsx
import Link from 'next/link';
import { List, ListItem } from 'h2d-glass-ui';

<nav aria-label="Settings">
  <List size="sm">
    <ListItem
      title="Profile"
      href="/settings/profile"
      current={pathname === '/settings/profile'}
      renderLink={(props) => <Link {...props} />}
    />
    <ListItem
      title="Billing"
      href="/settings/billing"
      current={pathname === '/settings/billing'}
      renderLink={(props) => <Link {...props} />}
    />
  </List>
</nav>;
```

<Canvas of={DataStories.Navigation} />

Pagination takes `getHref` and `renderLink` in the same way, when its pages are addresses. The
[List](?path=/docs/components-list--docs) page has the other looks and rows.

**A Stepper with the content of each step.** The Stepper draws the line of steps and nothing else:
show what the current step holds from the same `value`. Write the `Step`s in the component that
renders the `Stepper`. A client component that receives `Step`s from a Server Component gets them
already rendered, and the Stepper cannot read them.

```tsx
'use client';

import { useState } from 'react';
import { Button, Step, Stepper } from 'h2d-glass-ui';

export function Checkout() {
  const [value, setValue] = useState(0);
  return (
    <>
      <Stepper value={value} onValueChange={setValue}>
        <Step title="Cart" />
        <Step title="Delivery" />
        <Step title="Payment" />
      </Stepper>
      {value === 0 ? <Button onClick={() => setValue(1)}>Continue to delivery</Button> : null}
      {value === 1 ? <p>Where should we send it?</p> : null}
      {value === 2 ? <p>How would you like to pay?</p> : null}
    </>
  );
}
```

## App shell

`AppShell` is the frame of an application: a header, a sidebar with a navigation, the main content
and, if you want one, a footer. The CSS lays it out, so the HTML from the server is right at every
width. This is the least you write; each part has a page of its own, and
[Examples/App shell](?path=/docs/examples-app-shell--docs) has a whole application with the search,
the notifications, the theme and the account in the header.

```tsx
import {
  AppShell,
  AppShellBrand,
  AppShellFooter,
  AppShellHeader,
  AppShellMain,
  AppShellSidebar,
  Nav,
  NavItem,
} from 'h2d-glass-ui';

<AppShell brand={<AppShellBrand logo={<LogoMark />} name="Lumen" href="/" />}>
  <AppShellHeader>{/* search, notifications, the user */}</AppShellHeader>
  <AppShellSidebar>
    <Nav aria-label="Main">
      <NavItem href="/" icon={<HomeIcon />} active>
        Overview
      </NavItem>
      <NavItem href="/inbox" icon={<InboxIcon />} badge={12}>
        Inbox
      </NavItem>
    </Nav>
  </AppShellSidebar>
  <AppShellMain>{children}</AppShellMain>
  <AppShellFooter>© 2026 Lumen</AppShellFooter>
</AppShell>;
```

The header, the sidebar, the main and the footer must be direct children of `AppShell`. The footer
is optional, and so are the header and the sidebar: with no sidebar the page is one column.

### Server and client

`AppShell`, `Nav` and the widgets of the header (`SearchField`, `ThemeSwitch`, `UserMenu`) are
client components, since they keep state: a page that is a Server Component renders them, their HTML
comes from the server like that of any client component, and what it hands them as `children` stays
on the server. A shell that is given functions, such as `onCollapsedChange` below, is a small client
component of your own, which the Server Component renders with the page as `children`, so what is
in `AppShellMain` still stays on the server. `AppShellBrand` and `Indicator` need no client code at
all.

The navigation is data, drawn by a component that reads the path: a router's `Link` goes into
`NavItem` with `asChild`, and `active` comes from the current path (see
[Nav](?path=/docs/components-nav--docs#the-current-page-and-next-js)).

### Keep the sidebar folded

`AppShell` keeps the sidebar folded into a rail in its own state, which a reload would lose. Keep it
in a cookie, which the server can read when it sends the HTML, so that the page arrives already
folded:

```tsx
// app/(app)/layout.tsx: Server Component
const collapsed = (await cookies()).get('flg-sidebar')?.value === 'collapsed';
return <Shell defaultCollapsed={collapsed}>{children}</Shell>;

// shell.tsx: 'use client'
<AppShell
  defaultCollapsed={defaultCollapsed}
  onCollapsedChange={(c) => {
    document.cookie = `flg-sidebar=${c ? 'collapsed' : 'expanded'}; path=/; max-age=31536000; samesite=lax`;
  }}
>
```

`onCollapsedChange` is a function, so it can only be passed from a client component: that is why
the shell is one.

### Two rules for the document

On a page that renders an `AppShell`, and only there, the library sets two rules on the document.
Both are in a layer, so a rule of yours wins:

- `scroll-padding-top` on `<html>` is the height of the header, so that a focused control, a link to
  `#anchor` and a hit of find-in-page do not land under the sticky header.
- `body` has no margin, so that the frame touches the four edges of the screen.

If you set your own `scroll-padding-top` or margin, add the height of the header yourself with
`var(--flg-app-shell-header-offset)`. The [AppShell](?path=/docs/components-appshell--docs#rules-for-the-document)
page has the details.

### The theme, and no flash

A person who chose Dark would see a flash of light before `ThemeSwitch` has read what they chose.
`ThemeScript` in the `<head>` sets the theme before the first paint, and `suppressHydrationWarning`
on `<html>` tells React that the script changed the element:

```tsx
// app/layout.tsx
import { ThemeScript } from 'h2d-glass-ui';
import 'h2d-glass-ui/styles.css';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <ThemeScript />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

With next-themes, do not render `ThemeScript` (it has a script of its own): set
`attribute="data-flg-theme"` and pass its value to a controlled `ThemeSwitch`. A Content Security
Policy that needs a nonce is on the [ThemeSwitch](?path=/docs/components-themeswitch--docs) page.

### The Toaster, and text on the page

- Render `<Toaster />` outside `AppShell`. The header, the main and the footer are `inert` while the
  sheet of a narrow screen is open, and a toast inside one of them could be neither seen nor pressed.
- Put text that sits straight on the page, with no card behind it, in `--flg-text`, not in
  `--flg-text-muted`. The muted colour is tuned for text on glass, and is not guaranteed to reach
  AA on the bare gradient of the page (see the known gaps in Accessibility).

## Pick a theme

Without a `data-flg-theme` attribute the library follows the operating system's light or dark
preference. Set the attribute to force a theme, on `<html>` or on any subtree:

```html
<html data-flg-theme="dark"></html>
```

With next-themes, set `attribute="data-flg-theme"`.
