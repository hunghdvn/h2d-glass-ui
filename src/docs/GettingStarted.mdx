# Getting started

h2d-glass-ui is a glassmorphism component library for React 18.3+ and 19. It ships plain CSS and
works in React Server Components.

## Install

```bash
pnpm add h2d-glass-ui
```

## Load the styles once

```tsx
import 'h2d-glass-ui/styles.css';
```

All library CSS lives in the `flg` cascade layer, so any CSS you write outside a layer overrides it
without `!important`.

## Use a component

```tsx
import { Button, Card, CardContent, CardFooter, CardHeader, CardTitle } from 'h2d-glass-ui';

export function Upgrade() {
  return (
    <Card>
      <CardHeader>
        <CardTitle>Upgrade to Pro</CardTitle>
      </CardHeader>
      <CardContent>Unlimited sync and priority support.</CardContent>
      <CardFooter>
        <Button variant="ghost">Not now</Button>
        <Button>Upgrade</Button>
      </CardFooter>
    </Card>
  );
}
```

Phase 1 components: Surface, Card, Button, IconButton, Badge, Avatar, Divider, Spinner, Field,
Input, Textarea, Checkbox, RadioGroup and Switch. Phase 2 adds Dialog, Drawer, Popover, Tooltip,
DropdownMenu, ContextMenu, Select, Tabs, Accordion, Breadcrumb, Pagination and Toast.

## Overlays

Dialog, Drawer, Popover, Tooltip, the menus and Select are built on the native `<dialog>` element and
the Popover API, so there is no portal and no z-index to manage: an overlay renders next to its
trigger and sits above the page.

Toast is the exception. The `<Toaster />` has no trigger: it renders where you place it, as a
popover above the page. While a Dialog or Drawer is open it moves its region into that modal's host
(a portal), so the toasts can still be seen, clicked and read.

Put a `<Toaster />` once near the root of the app, then call `toast()` from client code:

```tsx
import { Toaster } from 'h2d-glass-ui';

export function App({ children }: { children: React.ReactNode }) {
  return (
    <>
      {children}
      <Toaster />
    </>
  );
}
```

A `<dialog>` that this library did not create is not part of its overlay stack. A modal one makes
the rest of the page inert, the toasts among it, so they sit under it and cannot be clicked; the
library's own Dialog and Drawer carry the toasts inside them instead. Open a modal through the
library's Dialog when toasts must stay reachable.

## Build a form

Wrap each control in a `Field` for its label, description and error. Every control is a native
form element underneath, so `FormData`, the browser's validation and form libraries work as usual.

```tsx
import { Field, Input } from 'h2d-glass-ui';

<Field label="Email" description="We only use it to send sign-in links." error={errors.email}>
  <Input name="email" type="email" autoComplete="email" />
</Field>;
```

## Pick a theme

Without a `data-flg-theme` attribute the library follows the operating system's light or dark
preference. Set the attribute to force a theme, on `<html>` or on any subtree:

```html
<html data-flg-theme="dark"></html>
```

With next-themes, set `attribute="data-flg-theme"`.
