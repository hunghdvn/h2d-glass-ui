# Theming

Every visual decision is a CSS custom property prefixed with `--flg-`. Override any of them in your
own CSS, outside a cascade layer, on every theme root:

```css
:root,
[data-flg-theme] {
  --flg-accent-start: #7c3aed;
  --flg-accent-end: #db2777;
}
```

Target `[data-flg-theme]` as well as `:root`: each element with that attribute re-declares every
theme token, so an override on `:root` alone does not reach a nested theme.

Derived tokens such as `--flg-glass-filter` and `--flg-accent-gradient` are computed from other
tokens once per theme root, and descendants inherit the finished value. Overriding an input such as
`--flg-glass-blur` or `--flg-accent-start` on an arbitrary element therefore does not recompute them
there. Override inputs on a theme root: `:root`, or an element with `data-flg-theme`.

## Light, dark and nested themes

`data-flg-theme="light"` or `"dark"` works on `<html>` or on any element, so a dark sidebar can sit
inside a light page. Without the attribute the operating system preference decides. With
next-themes, pass `attribute="data-flg-theme"` to its `ThemeProvider`.

## Performance

Every `Surface` is its own `backdrop-filter` layer, and each blur layer costs GPU time on every
frame it repaints. Avoid nesting many Surfaces: put plain content and controls inside one Surface
instead of giving each its own glass.
