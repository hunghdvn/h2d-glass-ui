# Pagination

## Which pages show

The row shows `boundaryCount` pages at each end (default 1), `siblingCount` pages on each side of
the current one (default 1), and an ellipsis for each gap. A gap of one page shows that page
instead, and the row keeps the same number of slots as the current page moves, so it does not
jump around. `count` below 1 counts as 1, and the page stays within 1 and `count`. A `count`,
`page`, `siblingCount` or `boundaryCount` that is not a finite number counts as 1, so
`page={Number(searchParams.page)}` shows page 1 when the address has no page.

## Buttons or links

- By default the pages are buttons: `onPageChange` gets the page, and you show it. At the ends
  the previous and next buttons have `aria-disabled="true"` and do nothing, but keep their place
  in the Tab order: a keyboard user who presses Next up to the last page stays on it.
- With `getHref`, every page is a link to `getHref(page)`, so the pages work without JavaScript
  and open in a new tab. A plain click calls `onPageChange`, and the browser follows the link. A
  click with Ctrl, Cmd, Shift or Alt, or with another mouse button, is left to the browser (a new
  tab or window, a download), and this Pagination stays on its page. At the ends, the previous and
  next links have no `href`, `role="link"` (an `<a>` without `href` has no role of its own) and
  `aria-disabled="true"`.

In a React Server Component, pass `getHref` from a client component of your own: a function
cannot cross from the server to a client component.

## Links from a router

By default a link is a plain `<a>`, so a click loads the page again. `renderLink` renders each link
that has an `href` (the pages, previous and next) as the link of your router. Pass it every prop it
gets: `onClick` is the library's handler, which calls `onPageChange`, and the router runs it before
it navigates. Previous and next are still wrapped by the library's button, which adds its classes and
`aria-label` to what you return, so the link must hand every prop and its `ref` down to its `<a>`;
the `Link` of Next.js and of React Router both do.

```tsx
'use client';

import { Pagination } from 'fl-glass-ui';
import Link from 'next/link';

export function Pages({ page }: { page: number }) {
  return (
    <Pagination
      count={12}
      page={page}
      getHref={(target) => `?page=${target}`}
      renderLink={(props) => <Link {...props} />}
    />
  );
}
```

- `renderLink` is a function too, so it must come from a client component, like `getHref`.
- The previous and next links at the ends have no `href`: they stay the library's `<a role="link"
aria-disabled="true">` and do not go through `renderLink`.
- A click your own handler cancels with `preventDefault` is ignored by the library: the page does
  not change and `onPageChange` is not called. Without `getHref`, `renderLink` is ignored, with a
  warning in development.

## Labels

The navigation is named "Pagination"; the arrows "Previous page" and "Next page"; each page
"Page 5" and so on. Change them with `aria-label`, `previousLabel`, `nextLabel` and
`getPageLabel`, for example to translate them.

## Accessibility

- It is a `nav` landmark. The current page has `aria-current="page"`, and the ellipses are
  hidden from assistive technology.
- The current page uses the accent wash with accent text, as a selected pill tab: see rows 7 and
  8 on the Accessibility page. With `prefers-contrast: more` it is solid accent.

## Do and don't

- Do use Pagination for long lists split into pages.
- Don't use it for steps of a task, or for a few items: show them all.
