# Field

```tsx
import { Field, Input } from 'fl-glass-ui';

<Field label="Email" description="We only use it to send sign-in links." required>
  <Input type="email" />
</Field>;
```

## Required

`required` shows an asterisk after the label and puts the native `required` attribute on the
control, which is what screen readers announce. The asterisk itself is hidden from them.

<Canvas of={Stories.Required} />

## Errors

Any `error` marks the field invalid: the control gets `aria-invalid="true"` and the error is read
after the description.

## Aside

`aside` puts content at the right of the label row, such as a character counter or the value of a
slider. It sits outside the label, so it does not become part of the control's name. A Field
without `aside` looks exactly as before.

<Canvas of={Stories.WithAside} />

Field does not hide the aside from screen readers. When they already get the content another way,
for example a value that the control announces itself, pass it with `aria-hidden="true"`:

```tsx
<Field label="Volume" aside={<span aria-hidden="true">60%</span>}>
  …
</Field>
```

## Accessibility

- The label points at the control through `for`, and the description and error are linked with
  `aria-describedby`, description first. Pass `id` to the Field or to the control directly inside
  it; the development build warns when a control deeper inside has an `id` the label cannot follow.
- A Field labels one control. The development build warns when it has several directly inside.
- A `RadioGroup` placed directly inside `Field` is named by the label through `aria-labelledby`.
  Keep it a direct child (a Fragment around it is fine): wrapped in another element, the Field
  cannot recognise it, and the development build warns.
- With `Checkbox` and `Switch`, the control's own children usually are the label. Use `Field` for
  the description and the error only.

## Do and don't

- Do write errors that say how to fix the value ("Use at least 8 characters.").
- Don't pass props such as `aria-invalid` or `required` to the control unless you mean to replace
  what the Field provides: a prop passed directly to the control wins. An `aria-describedby` you
  pass is added after the Field's description and error.
